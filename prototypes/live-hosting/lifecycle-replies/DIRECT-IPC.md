# Direct IPC inventory — source review, incomplete runtime validation

This inventories direct `validatedIpcMain.on/once/handle` registrations and raw Electron registration sites across `src/vs`. It is a starting boundary inventory, not an exhaustive security audit or a claim these paths pass. The experiment stopped at shared-host recovery failure before implementing and exercising the remaining paths.

| Path | Intended ownership / review boundary | Current finding and runtime coverage |
| --- | --- | --- |
| `platform/lifecycle/electron-main/lifecycleMainService.ts` | Exact main-owned workbench/document and pending phase | Revised here: random phase channels, sender/frame, document credential/generation and window payload checks before consumption; revocation interrupts waits. Sampled actual cancel/save/reload plus transport controls passed. Auxiliary, stale queued-message, destruction and full joiner/race matrix remain unperformed. |
| `platform/diagnostics/electron-main/diagnosticsMainService.ts` | Reply belongs to the requested remote workbench/document and diagnostic operation | Fixed per-window callback name and `once` without owner validation; timeout does not remove listener. Source only. Needs correction before runtime acceptance. |
| `platform/sharedProcess/electron-main/sharedProcess.ts` | Authorized workbench role; port and shared-service authority bound to requester lifetime | After async readiness/connect, checks destruction but not generation; replacement may reuse sender. Source only. Port transfer and downstream service scope untested. |
| `platform/terminal/electron-main/electronPtyHostStarter.ts` | Own workbench's terminal connection and scoped operations | Direct sender routing, but no document binding or downstream target audit. Source only. |
| `platform/agentHost/electron-main/electronAgentHostStarter.ts` | Provider-neutral authorized connection; restart/policy are explicitly scoped application/coordinator operations | Async connection checks destruction, not replacement generation; restart and policy listeners lack explicit role ownership. Tracking is by WebContents ID. Source only; no provider acceptance. |
| `platform/auxiliaryWindow/electron-main/auxiliaryWindowsMainService.ts` | Auxiliary sender's main-established opener/home workspace | Parent assignment takes supplied mainWindowId. Hosting uses retained views, so native did-create-window assumptions also need review. Source only. |
| `code/electron-main/app.ts`: shell environment | Bootstrap owner and intended internal roles; no fallback to a neighbour or privileged global environment | Maps sender to code window, otherwise global environment fallback; async result has no explicit generation fence. Source only. |
| `code/electron-main/app.ts`: zoom/devtools/raw reload | Current owning document; reload must preserve lifecycle safeguards | Zoom maps sender, devtools targets sender, raw reload calls sender.reload directly. Raw reload is a known source bypass needing correction, not a runtime result here. |
| `base/parts/contextmenu/electron-main/contextmenu.ts` | Owning workbench/document for menu, click and dismissal | Delayed callbacks send to sender without generation check; callback channel is supplied. Source only. |
| `platform/protocol/electron-main/protocolMainService.ts` | Configuration capability belongs to intended bootstrap document; pre-bootstrap authorization must avoid a circular dependency | UUID channel returns config with origin/frame validation but no owner; only caller is `windowImpl.ts`. Source only. |
| `base/parts/ipc/electron-main/ipc.electron.ts` | Generic service connections bound to authenticated current document; internal roles remain separate | Existing generation/connection adapter retained. Its earlier results are not rerun or inherited as passes here. |
| `base/parts/ipc/electron-main/ipcMain.ts` | Common origin/frame gate, not per-operation authorization | `once` consumes before validation; lifecycle now uses removable `on` listeners, diagnostics still does not. The wrapper's about:blank/missing-URL allowances are not proof of identity. |
| `platform/utilityProcess/electron-main/utilityProcess.ts` | Extension/worker effects and ports belong to the logical workbench lifetime | Existing generation checks retained. Native `closed` still terminates each bound child: shared-host destruction during crash recovery exited neighbouring extension hosts in this run. |

Search used: `rg -n 'ipcMain\.(on|once|handle)|validatedIpcMain\.(on|once|handle)' src/vs --glob '*.ts'`, plus delayed `send/postMessage`, utility ports and protocol-object callers. Dynamic registration and downstream port RPC authorization still need further tracing.

Do not fix these by granting all renderers application authority or denying all global operations. Preserve legitimate project, Agents, shell, auxiliary and internal roles. The next experiment must correct incomplete adapters before testing their corresponding requirements and retain the entire original staged gate.
